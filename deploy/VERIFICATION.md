# Локальная проверка — 16 сентября 2026

Результат: ALL FLOW CHECKS PASSED (deploy/check-flow.py), 13 unit-тестов без ошибок.
Проверка выполнена в отдельном Docker Compose проекте bookinghotel-flow-check через gateway на 127.0.0.1:18080. Существующий проект bookinghotel и его базы не изменялись.

Проверено:

- Регистрация USER, вход, создание каталога тестовым ADMIN и чтение каталога через gateway.
- При клиентских pricePerNight=0.01 и nights=1 сервер использовал 5000 × 3 ночи = 15000. Legacy-поля необязательны и не влияют на расчёт.
- NEW → PAYMENT_PENDING через Kafka; результат резервирования и команда оплаты сохранены в БД.
- Отказ при нехватке номеров, атомарное резервирование; из двух конкурентных заявок на один номер прошла одна.
- Повтор команды не создал второй резерв или второй платёж. Повторная доставка результата не повторяет бизнес-переход.
- Чужой платёж недоступен. Подтверждение до оплаты отклоняется.
- Тестовая FAILED-оплата → CANCELLED → освобождение номеров; повторное бронирование на эти даты возможно.
- Тестовая SUCCEEDED-оплата → PAID → CONFIRMED после действия администратора.
- Бронь и outbox сохраняются при отключённой Kafka; после перезапуска booking-service/Kafka поток продолжается. Gateway восстанавливает доступ при смене IP без собственного перезапуска.
- После пересоздания контейнеров четырёх БД и Kafka сохраняются аккаунт, подтверждённая бронь и успешный платёж.
- Custom-format dumps четырёх заполненных тестовых БД созданы. Дамп booking-db восстановлен в новую пустую тестовую БД, статус CONFIRMED совпал. Временная восстановленная БД удалена; оригинальные данные и дампы сохранены.
- Регулярный backup-сервис работает без root, первый запуск создал восемь dumps; SHA256SUMS совпали, healthcheck прошёл. Следующий запуск назначен скриптом через 86400 секунд; ожидание суток не выполнялось.

Unit-тесты: KafkaEventRoutingTests — 4, BookingPricingTests — 3, BookingSagaTests — 3, PaymentServiceTests — 3.
Собраны auth, catalog, booking, payment, gateway и service-discovery. Compose-конфигурация, синтаксис backup-скриптов и git diff --check проходят.

Ограничения: это локальный тестовый MVP, не проверка удалённого сервера. Реального списания денег нет; demo выключен по умолчанию. Публичный TLS, нагрузка, остальные REST-потоки и общий disaster-recovery всех БД/Kafka не проверялись. Для production нужны выбранный платёжный провайдер, сервер/домен, внешнее зашифрованное хранилище backup и политика хранения.

Тестовый стек после проверки остановлен без удаления томов. Разовые копии находятся в игнорируемой Git папке backups; автоматические — в томе bookinghotel-flow-check_database-backups-data. Инструкция повторного запуска — в корневом README.md.
